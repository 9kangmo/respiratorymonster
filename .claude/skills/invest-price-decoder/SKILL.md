# 가격 판독기 (Price Decoder)

적정주가를 계산하지 않는다. 거꾸로 묻는다: **이 가격은 회사에 무엇을 요구하는가?**
("중고차에 5천만원이 붙어 있으면, 그 성능이 실제로 나오는 차인가?")

## 시작 전에 (모든 투자 스킬 공통)
1. `docs/invest/principles.md`(절대 규칙)와 `docs/invest/bundle-format.md`(출력 형식)를 읽는다.
2. 포트폴리오 컨텍스트: `.data/*.invest.json`이 있으면 `holdings`(ticker·name·assetType·currency·sector), `watchlist`, `themes`, `events`만 읽는다. 없으면(배포 모드) 사용자에게 보유·관심 종목을 묻는다. 수량·평균단가는 필요할 때만 쓴다.
3. 오늘 날짜와 시간대(기본 Asia/Seoul)를 확인한다.

## 절차
1. 입력값을 모은다 (모두 출처 필수, 단위는 백만 · 백만 주):
   - 현재 주가, 희석 발행주식수, 순부채(총차입금 − 현금·단기투자, 순현금이면 음수)
   - 기준 FCF = 최근 회계연도(또는 TTM) 영업현금흐름 − CAPEX
   - 최근 5~6년 FCF 이력, 매출 이력
   - WACC 가정과 근거 (무위험이자율 + β × 시장위험프리미엄, 부채비용 반영), 영구성장률(보통 2~3%), 예측 기간(기본 10년)
2. 번들 초안(`valuations` 1개)을 쓰고 **반드시 코드로 계산한다**:
   `npm run -s invest -- dcf <파일>` → 요구 성장률, 과거 CAGR, 이상치, WACC × 영구성장률 민감도 표가 나온다. 이 출력의 숫자만 인용한다. 암산 금지.
3. 이상치(FCF가 직전 3년 평균 대비 ±40% 이상)가 나오면 원인(일회성 세금·운전자본·M&A 등)을 찾아 `[사실]`로 적는다. 기준 FCF를 정상화해야 하면 두 버전을 모두 계산한다.
4. 리포트(`reports[0]`, skill `price`):
   - 입력값·출처 표, WACC·영구성장률 가정 근거
   - 코드 출력의 요구 성장률 vs 과거 성장률 ("앱 계산 참조"라고 쓰거나 dcf 출력 표를 그대로 붙인다)
   - 민감도 표 — 하나의 할인율에 결론을 걸지 않는다
   - **확인할 질문**: "이 성장이 가능하려면 무엇이 사실이어야 하는가" 3가지 (예: 서비스 매출 비중이 X까지 늘어야 한다 → 스토리 리더로 확인)
   - "싸다/비싸다/사도 된다" 결론 금지
5. 앱은 `valuations` 값으로 같은 계산을 다시 해서 화면에 보여 준다.

## 저장 (모든 투자 스킬 공통)
1. 번들을 `invest-inbox/drafts/<YYYYMMDD-HHMM>-<스킬>[-<TICKER>].json`에 쓴다.
2. `npm run -s invest -- check <파일>`로 검증한다. `WARN`이 나오면 원인을 고친다(출처 추가, 매매 표현 제거, 웹 출처의 페이지 번호 삭제). 고칠 수 없으면 그대로 두고 사용자에게 알린다.
3. `npm run -s invest -- save <파일>`로 `invest-inbox/`에 넣는다. 로컬 앱은 화면을 열 때 자동으로 가져간다. 배포 앱을 쓰면 사용자에게 파일을 **가져오기** 화면에 올리라고 안내한다.
4. 채팅에는 리포트 본문 요약과 "원문 재확인 필요" 목록, 저장 경로를 보여 준다. 매매 의견으로 끝맺지 않는다.
