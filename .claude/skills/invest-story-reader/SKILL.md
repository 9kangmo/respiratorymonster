# 스토리 리더 (Story Reader)

요약 카드가 스냅샷이라면 이건 지난 2~3년의 **영화**다. 수백 페이지짜리 문서를 나란히 놓고 비교하는 일을 대신한다.

## 시작 전에 (모든 투자 스킬 공통)
1. `docs/invest/principles.md`(절대 규칙)와 `docs/invest/bundle-format.md`(출력 형식)를 읽는다.
2. 포트폴리오 컨텍스트: `.data/*.invest.json`이 있으면 `holdings`(ticker·name·assetType·currency·sector), `watchlist`, `themes`, `events`만 읽는다. 없으면(배포 모드) 사용자에게 보유·관심 종목을 묻는다. 수량·평균단가는 필요할 때만 쓴다.
3. 오늘 날짜와 시간대(기본 Asia/Seoul)를 확인한다.

## 절차
1. 최근 3개 회계연도의 사업보고서에서 **사업 개요 · 리스크 요인 · MD&A**를 찾는다 (사용자가 파일을 주면 그 파일을 우선, 출처에 페이지).
2. 연도별로 문장을 대조한다:
   - **새로 등장한 문구**, **사라진 문구**, **톤이 바뀐 표현** (예: "강력한 성장" → "안정적 성장", "예상한다" → "기대한다")
   - 각 항목: 이전 원문 인용 → 이후 원문 인용 → 출처(연도, URL/페이지) → `[해석]` 한 줄
3. 최근 4~8개 분기 어닝콜(또는 실적 발표 자료)에서 **경영진 자신감**을 분기별 표로 정리한다 (근거 인용 포함, 높음/보통/낮음은 `[해석]`).
4. **가이던스 vs 실제** 표: 약속한 숫자 → 실제 달성치 → 출처. 못 찾으면 `[확인 필요]`. 차이는 직접 계산하지 말고, 필요하면 코드로 계산한다.
5. **바뀐 것 / 바뀌지 않은 것**. 변화가 없으면 `[변화 없음]`이라고 쓴다 — 억지로 스토리를 만들지 않는다.
6. **다음 실적에서 확인할 포인트** 3개. 매매 의견 금지.
7. 한국 상장 기업이면 "어닝콜 전문이 공개되지 않아 IR 자료·기사 기반이며 정밀도가 낮다"를 본문 맨 앞에 적는다.
8. 결과: `reports[0]` (skill `story`), 다가오는 실적일은 `events`.

## 저장 (모든 투자 스킬 공통)
1. 번들을 `invest-inbox/drafts/<YYYYMMDD-HHMM>-<스킬>[-<TICKER>].json`에 쓴다.
2. `npm run -s invest -- check <파일>`로 검증한다. `WARN`이 나오면 원인을 고친다(출처 추가, 매매 표현 제거, 웹 출처의 페이지 번호 삭제). 고칠 수 없으면 그대로 두고 사용자에게 알린다.
3. `npm run -s invest -- save <파일>`로 `invest-inbox/`에 넣는다. 로컬 앱은 화면을 열 때 자동으로 가져간다. 배포 앱을 쓰면 사용자에게 파일을 **가져오기** 화면에 올리라고 안내한다.
4. 채팅에는 리포트 본문 요약과 "원문 재확인 필요" 목록, 저장 경로를 보여 준다. 매매 의견으로 끝맺지 않는다.
