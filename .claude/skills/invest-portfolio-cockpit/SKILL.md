# 포트폴리오 콕핏 (Portfolio Evaluator)

종목별 카드를 모아 포트폴리오 전체를 진단한다. 수치는 앱이 코드로 계산한다(`src/lib/invest/calc.ts` → 앱의 **포트폴리오 콕핏** 화면).

## 시작 전에 (모든 투자 스킬 공통)
1. `docs/invest/principles.md`(절대 규칙)와 `docs/invest/bundle-format.md`(출력 형식)를 읽는다.
2. 포트폴리오 컨텍스트: `.data/*.invest.json`이 있으면 `holdings`(ticker·name·assetType·currency·sector), `watchlist`, `themes`, `events`만 읽는다. 없으면(배포 모드) 사용자에게 보유·관심 종목을 묻는다. 수량·평균단가는 필요할 때만 쓴다.
3. 오늘 날짜와 시간대(기본 Asia/Seoul)를 확인한다.

## 절차
1. 보유 종목의 자산 유형을 확인한다. 지수·섹터 ETF에 구성종목(`constituents`)이 비어 있으면, 운용사 공식 페이지에서 상위 10개 구성종목과 비중을 찾아 리포트 표로 제시하고 "앱의 종목 수정 화면에 입력하면 숨은 중복이 계산된다"고 안내한다(출처 URL 필수).
2. 비중·HHI·환율 민감도가 필요하면 앱 화면 값을 인용하거나, 직접 계산해야 할 때는 코드로 계산한다(암산 금지).
3. 리포트(`reports[0]`, skill `cockpit`, ticker 없음):
   - **자산 유형별 평가 잣대**: 개별주 → 펀더멘털·역DCF / 지수 ETF → 지수 전체 이익·밸류에이션 / 원자재 ETF(금 등) → 펀더멘털 없음, 실질금리·달러 방향 / 채권 ETF → 듀레이션·신용
   - **집중·중복의 의미** `[해석]` (예: 개별주 + 그 종목 비중이 큰 지수 ETF)
   - **환율 시나리오**: 원/달러 ±10%에서 원화 평가액 변화 (코드 계산값)
   - **더 파볼 곳**: 어떤 종목에 어떤 스킬을 돌릴지
4. 리밸런싱·세금은 계산과 시나리오만. "비중을 줄여라/늘려라" 금지.

## 저장 (모든 투자 스킬 공통)
1. 번들을 `invest-inbox/drafts/<YYYYMMDD-HHMM>-<스킬>[-<TICKER>].json`에 쓴다.
2. `npm run -s invest -- check <파일>`로 검증한다. `WARN`이 나오면 원인을 고친다(출처 추가, 매매 표현 제거, 웹 출처의 페이지 번호 삭제). 고칠 수 없으면 그대로 두고 사용자에게 알린다.
3. `npm run -s invest -- save <파일>`로 `invest-inbox/`에 넣는다. 로컬 앱은 화면을 열 때 자동으로 가져간다. 배포 앱을 쓰면 사용자에게 파일을 **가져오기** 화면에 올리라고 안내한다.
4. 채팅에는 리포트 본문 요약과 "원문 재확인 필요" 목록, 저장 경로를 보여 준다. 매매 의견으로 끝맺지 않는다.
